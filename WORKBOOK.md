Synergrowth Inspection AppParticipant Workshop & Lab GuideWelcome to the Synergrowth Mobile App Development Workshop! Over the next two days, we will explore, modify, and build upon a React Native mobile application used for visual quality inspection on the manufacturing floor.The Goal: By the end of Day 2, you will understand how a modern React Native (Expo) app is structured, how data flows between screens, how to use the device camera, and how to connect to a cloud AI API.🛠 Prerequisites ChecklistBefore we begin, ensure you have the following installed:[ ] Node.js (LTS version recommended)[ ] Git[ ] VS Code (or Cursor / your preferred editor)[ ] Expo Go app installed on your physical Android/iOS device (Available on Google Play and the App Store)☀️ DAY 1: Foundation & Data FlowSession 1: Get Up and RunningOur app workflow is simple: Capture Image → Send to Cloud API → Get PASS/FAIL Result.Let's get the app running locally on your machine and phone.Step 1: Clone & InstallOpen your terminal and run:git clone [https://gitlab.com/JiaYee/synergrowth-inspection-app.git](https://gitlab.com/JiaYee/synergrowth-inspection-app.git)
cd synergrowth-inspection-app
npm install
Step 2: Start the Development Servernpx expo start
Step 3: Run on Your PhoneOpen the Expo Go app on your phone.Scan the QR code shown in your terminal.The app will bundle and open.Walkthrough: Tap through the app! Go from Welcome → Selection → Product → Component → Camera → Result. Notice how the screens flow. (Note: The app is currently in DEMO MODE, meaning it isn't hitting the real server yet).Session 2: Project Structure & How Screens ConnectExpo Router handles our navigation. Every file inside the app/ folder becomes a screen in our application.🗺️ File Tourapp/ - Your app's screens (navigation routes).components/ - Reusable UI building blocks (buttons, text styling).constants/ - Configuration, mock data, and theme colors.services/ - API connections and Global State (Context).💻 LAB 1: UI & Layout TweaksOpen app/(tabs)/index.tsx (The Welcome Screen). Let's customize it!Change the Text: Find the title string and change it to something custom (e.g., "My Factory Inspector"). Save the file and watch your phone update instantly (Hot Reloading!).Change Button Color: Find the button's backgroundColor in the styles and change it to 'blue' or '#FF5733'.Flexbox Challenge: Move the logo so it sits below the title instead of above it. Modify the StyleSheet to make the start button take up the full width of the screen.Session 3: Selection Screen — Dropdowns, State & DataData needs to flow from the Selection screen to the rest of the app. We use React Context to achieve this.💻 LAB 2: Adding New DataYour factory just opened a new production line! Let's add it to the app.Open constants/mock-data.ts.Find the PRODUCTION_LINES array.Add a new entry for LINE_D.Add your own name to the OPERATORS array.Check the Selection screen on your phone to verify the dropdowns updated.💻 LAB 3: Global State ExpansionWe need to track the "Batch Number" for the inspection.Open services/inspection-context.tsx.Add batchNumber: string to the context type and the initial state object.Open app/selection.tsx.Add a TextInput field so the user can type in a batch number.Ensure updating this input updates the global context.Session 4: Product & Component ScreensOnce a user selects their station, they move to the Product screen, which tells them what to inspect. The Component screen loops through the specific parts of that product.💻 LAB 4: Dynamic UI UpdatesOpen app/product.tsx.Add a new line of text below the product name that displays the currently selected Line and Station (e.g., "Line A / Station 1"). Hint: Extract these variables from useInspection().💻 LAB 5: Adding a New ProductOpen constants/mock-data.ts.Create a new product called PRODUCT_ALPHA. Give it an id, name, image, and an array of 3 components. Make sure the components have coordinates: { x1, y1, x2, y2 }.Select PRODUCT_ALPHA in the app and tap through its components.💻 LAB 6: UX ImprovementsOpen app/component.tsx.To help the operator know where they are, add a text indicator: "Inspecting component {current + 1} of {total components}".End of Day 1. Great job!☀️ DAY 2: Camera, API, & ProductionSession 6: Camera Screen — Capture & CropToday we connect to hardware! The camera screen handles permissions, taking the photo, and cropping it to the highlighted region.💻 LAB 7: Adjusting the Camera GuideOpen app/camera.tsx.Find the guide box overlay styles. Change its width from 70% to 50%.Change its border color to blue.Add instructions above the box that say: "Align component here".💻 LAB 8: Image PreviewCurrently, when you snap a photo, it immediately says "Analyzing...". Let's show the user what they captured.In app/camera.tsx, find the state where the image is captured but before the API call finishes.Render an <Image /> component displaying the croppedUri as a small thumbnail on the screen.Session 7: API Integration — Predict & SubmitIt's time to connect to the cloud. Our backend is hosted on Render.com.💻 LAB 9: Going LiveOpen constants/config.ts.Change DEMO_MODE = true to DEMO_MODE = false.Capture a photo. Your app is now sending a real FormData POST request to the cloud AI!💻 LAB 10: Handling Network Errors gracefullySometimes factory Wi-Fi drops out.Open app/camera.tsx.When the predict API fails (throws an error), display a "Retry" button.When tapped, the retry button should call the predictImage function again using the already captured croppedUri (so the user doesn't have to retake the photo).Session 8: Result Screen — Human-in-the-LoopAI isn't perfect. The Result screen allows the operator to see the AI's prediction and either confirm it or override it (Human-in-the-loop).💻 LAB 11: Color Coded ResultsOpen app/result.tsx.Wrap the machine's PASS/FAIL text in a View.Make the backgroundColor of the View Green if the result is PASS, and Red if the result is FAIL.💻 LAB 12: End of Inspection AlertRight now, the app just loops back. Let's make the finish line clearer.In app/result.tsx, find the logic that triggers when the last component is submitted.Show a native Alert or a custom Modal saying: "All components inspected successfully!"Add a button to that alert that routes the user back to the home screen (router.replace('/')).Session 9 & 10: Theming & Building the APKLet's prepare the app for actual factory deployment by branding it and packaging it.💻 LAB 13: RebrandingOpen constants/theme.ts. Change the primary brand color.Open app.json. Change the name of the app and background color of the splash screen.Restart the Expo server to see your new branding taking effect.📦 LAB 14: Creating the Android APK (EAS Build)To run without Expo Go, we need a standalone .apk file.(Your trainer will guide you through this step on the projector)npx eas build --platform android --profile preview
Once built, download the APK, install it on your Android device, and run a full end-to-end inspection!🎯 Wrap-Up & Cheat SheetCongratulations!
